# Chrome Web Store preparation

The installable extension and the listing materials are separate. Upload only the installable
shadowfence-0.2.1.zip as the extension package, then upload the images in their dedicated fields.
Do not upload the source ZIP or the entire Store kit as the extension package.

The SVG promotional sources and outlined brand lettering are included for future exports. No
font files or remote fonts are distributed in the extension. The extension ZIP includes 16, 24,
32, 48 and 128px PNG icons and explicit toolbar icon mappings.

## Release checks

- Check the included SHA256SUMS against the installable ZIP.
- Use the passing CI run and the supplied browser reports as the recorded verification evidence.
- Stable Chrome for Testing exercises the production extension and captures the Store screenshots.
- A backup is exported and restored between two distinct unpacked extension IDs.
- Page CPU throttling is a simulation, not a guarantee about real low-end hardware or worker speed.
- Browser and image tests do not constitute an independent security audit.

## Publisher/dashboard steps

Account readiness has not been verified: browser access to the Google-account page was declined
on 23 October 2026. No Store item was created, no listing was uploaded, and nothing was submitted
for review in this preparation run.

When the publisher opens the dashboard:
1. Confirm the intended publisher account and its current verification requirements. Contact-email
   verification and two-step verification are required. Resolve any identity/trader declarations
   shown by the account; do not guess those answers.
2. Upload the installable ZIP as a draft. Keep the generated item ID for subsequent updates.
3. Use LISTING.md for the description, purpose, privacy explanation and reviewer instructions.
4. Add the public privacy-policy URL and support URL. Review and certify the data-use declarations.
5. Upload the icon and screenshots in numbered order, with the dark image check first. Add the
   small tile; use the marquee if desired.
6. Select the intended distribution regions/visibility and finish any remaining dashboard fields.
7. Save the draft and check the dashboard's actual validation messages.
8. Submit for review only after the owner explicitly approves that submission. The original
   project brief reserves Chrome Web Store publication for explicit approval.

No new account, fee, paid service or agreement is needed to use the files in this kit. Publisher
registration or account-specific requirements may still apply in the actual dashboard.

## Moving an existing vault

An unpacked installation and a Store installation can have different extension IDs and therefore
separate IndexedDB storage. Before uninstalling or moving an unpacked folder, export an encrypted
backup. Restore into the new empty installation with the original backup passphrase and verify the
identities and references before removing the old copy. Version-2 backups require 0.2 or later.

## Recreate the assets

After a production build and fixture setup, run:

```sh
node tests/store-screenshots.mjs
```

This defaults to Playwright Chromium. In Linux CI, scripts/fetch-stable-chrome.py obtains the
current Stable Chrome for Testing build from Google's index and supplies its executable path.
The vector promotional images are generated by scripts/store-art.mjs. All results go under
`test-results/store`, with validation evidence in `test-results/store-assets-report.json`.
